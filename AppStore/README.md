# App Store metadata

The App Store Connect texts, kept in the project. Nothing is uploaded
automatically — open the file, copy the contents, paste it into the matching
field in App Store Connect.

The folders are named after the fastlane convention (`cs`, `en-US`, `en-GB`), so
if you ever decide to move to `fastlane deliver`, renaming `AppStore/` to
`fastlane/metadata/` is all it takes.

This guide is not tied to a version and names none on purpose. The version being
prepared is whatever `MARKETING_VERSION` in `jetshot.xcodeproj/project.pbxproj`
says, the texts here describe that version, and the
[release procedure](#release-procedure) is the same for every release. The App
Store Connect record is id `6754814450`, localised in English (U.S.), English
(U.K.) and Czech — one folder each.

## Where everything goes

App Store Connect → **Apps → Jetshot → iOS App → <version> Prepare for
Submission**. There is a language switch at the top (**English (U.S.)** /
**English (U.K.)** / **Czech**) — every field is filled in separately for each
language.

| Field in App Store Connect | File | Limit |
|---|---|---|
| App Name | `<language>/name.txt` | 30 characters |
| Subtitle | `<language>/subtitle.txt` | 30 characters |
| Promotional Text | `<language>/promotional_text.txt` | 170 characters |
| Description | `<language>/description.txt` | 4000 characters |
| Keywords | `<language>/keywords.txt` | 100 characters |
| What's New in This Version | `<language>/release_notes.txt` | 4000 characters |
| App Preview and Screenshots | generated by the scripts, see [screenshots.md](screenshots.md) | 3–10 images |

The check below prints the current character counts, NFC-normalised and excluding
trailing newlines, the way App Store Connect counts them.

Alternative names, subtitles and keyword sets — and the competitor research the
current ones came out of — are in [alternatives.md](alternatives.md).

Checking it. The limits are the easy half; the three checks after them are the
ones that catch real mistakes: a word paid for twice across two indexed fields, a
stray space in the keyword list, and a paragraph left wrapped at 80 columns.

```bash
python3 - <<'PY'
import os,re,unicodedata
lim={'name.txt':30,'subtitle.txt':30,'keywords.txt':100,
     'promotional_text.txt':170,'description.txt':4000,'release_notes.txt':4000}
bad=0
for loc in ('en-US','en-GB','cs'):
    # Czech diacritics must be counted composed - App Store Connect counts NFC.
    d=lambda f:unicodedata.normalize('NFC',
        open(os.path.join('AppStore',loc,f),encoding='utf-8').read()).rstrip('\n')
    for f,m in lim.items():
        n=len(d(f)); bad+=n>m
        print(f'{loc:7}{f:22}{n:5}/{m}', 'OK' if n<=m else 'OVER!')
    # a word in two indexed fields is paid for twice and indexed once
    t=lambda f:set(re.findall(r'[\wÀ-ſ]+', d(f).lower()))
    for a,b in (('name.txt','subtitle.txt'),('name.txt','keywords.txt'),
                ('subtitle.txt','keywords.txt')):
        ov=t(a)&t(b); bad+=bool(ov)
        if ov: print(f'{loc:7}DUPLICATED {a} x {b}: {sorted(ov)}')
    # a space after a comma silently costs one of the 100 characters
    if ', ' in d('keywords.txt'): bad+=1; print(f'{loc:7}KEYWORDS: space after comma')
    # App Store Connect keeps newlines - a paragraph has to be a single line
    L=d('description.txt').split('\n')
    for i,l in enumerate(L[:-1]):
        if (l.strip() and L[i+1].strip() and not l.isupper() and not l.startswith(chr(8226))
                and not L[i+1].startswith(chr(8226))
                and not l.rstrip().endswith(('.','!','?',':','…'))):
            bad+=1; print(f'{loc:7}DESCRIPTION line {i+1} wrapped mid-paragraph')
print('ALL CLEAN' if not bad else f'{bad} problem(s)')
PY
```

## Notes on the individual fields

- **App Name** — has to be globally unique, and `Jetshot` already is. The original
  name `Jetshot – Space Shooter` left seven of the thirty characters unused;
  `Jetshot: Offline Space Shooter` spends them on the one near-head term this app
  can actually compete on. The reasoning, and the alternatives if it ever needs to
  change, are in [alternatives.md](alternatives.md). On the home screen the app
  is just "Jetshot" (`INFOPLIST_KEY_CFBundleDisplayName`, and both languages in
  `InfoPlist.xcstrings`): a label under an icon has room for about a dozen
  characters, and "Jetshot – Space Shooter" showed as "Jetshot – Sp…". Apple only
  requires that the home-screen name not differ in *meaning* from the store name.
- **Keywords** — separate with commas and **no spaces** (a space counts towards
  the limit). Do not repeat words already in the name or subtitle, Apple indexes
  those separately; that is why *offline*, *space*, *shooter*, *retro*, *arcade*
  and *ads* are absent from the English list and *vesmírná*, *střílečka*,
  *arkáda* and *reklam* from the Czech one. Two Czech entries look like breaches
  and are not: *vesmír* stands beside *vesmírná* in the name, and *hra* stands
  beside *hry*, because Apple's Czech stemming cannot be relied on to pair them
  the way it pairs an English singular with its plural.
- **Description** — write each paragraph as **one long line**. App Store Connect
  keeps newlines exactly as pasted, so a paragraph wrapped at 80 columns in the
  editor comes out ragged on the device while every other paragraph reflows around
  it. Note also that on iOS the description is **not indexed for search** — it is a
  conversion field only, so keywords in it buy nothing. The original listing said
  "arcade space shooter" nine times for exactly that reason and it bought nothing;
  the current text spends the space on the first three lines instead, which is all
  most people ever see.
- **Promotional Text** — the only field that can be changed without a new build
  and without review. Useful for seasonal or topical messages. Like the
  description, it is not indexed for search.
- **What's New** — `release_notes.txt` is rewritten for every version and holds
  only what changed since the previous one, so it always describes the version in
  `MARKETING_VERSION`. Earlier versions' notes are in the git history
  (`git log -p -- AppStore/en-US/release_notes.txt`).

## Settings that are not filled in with text

**App Information** (shared across all languages):

- Primary Category: **Games → Action**
  (matches `LSApplicationCategoryType = public.app-category.action-games`)
- Secondary Category: **Games → Arcade**
- Content Rights: contains no third-party content
- Age Rating: **4+**, which is what the listing already carries. The honest answer
  to *Cartoon or Fantasy Violence* is arguable — the game destroys ships — but
  everything on screen is an abstract vector shape, there are no characters and no
  blood, and Apple has accepted 4+ since January. If you ever re-run the
  questionnaire, watch *Contests* and *Unrestricted Web Access* → both No.

**App icon:** generated, not drawn by hand — `swift Tools/gen_icon.swift
jetshot/JetshotIcon.icon/Assets` writes the two layers Icon Composer composites.
The reasoning behind the design, and the competitor grid it came out of, is in that
file's header; the short version is that the twelve icons ranking for "space
shooter" are all the same crowded three-quarter render of a metallic fighter, so
this one is a single glowing vector ship on near-black with a lot of empty space
around it, and is the only dark tile in the row.

Two settings in `icon.json` are load bearing and were arrived at by building and
looking at the result in the app bundle rather than by guessing. `"specular": false`
turns off Icon Composer's edge highlight and background blur, which desaturated the
neon and turned the exhaust flames tan; `"translucency": {"enabled": false}` keeps
the clear appearance from washing the same colours out again. There is a light grey
hairline around the finished tile that no setting removes — it is the chiclet
highlight Apple's own renderer bakes into the legacy fallback PNGs, and every Icon
Composer app has it.

**Pricing and Availability:** Free, all countries.

**App Privacy:** *Get Started* → **"No, we do not collect data from this app"**.
The game has no advertising SDKs, no analytics and no third-party libraries; it
links only Apple frameworks. It does mirror progress to
`NSUbiquitousKeyValueStore`, but data held in the *user's own* iCloud account,
which the developer cannot read, is not "collected" under Apple's definition — so
the answer stays No. Say so in the review notes anyway, because the iCloud
entitlement is visible to the reviewer; it is already in
[review-notes.txt](review-notes.txt).

A **privacy policy URL is mandatory, per localisation**. The pages live on
`RobertLib/roblib`'s `main` branch —
[English](https://github.com/RobertLib/roblib/blob/main/privacy-policy-jetshot.html)
and [Czech](https://github.com/RobertLib/roblib/blob/main/privacy-policy-jetshot-cs.html)
— and their source is the local texts in [privacy-policy/](privacy-policy/). Those
describe every value the game stores: `completedLevels`, `levelScores`,
`levelStars`, `levelWeapons`, `endlessRecords`, `levelMedals`, the reset counter
`progressEpoch` and the reset time `progressResetAt`; the small marker iCloud holds
beside each progress value with the reset counter it was saved under (for example
`completedLevels.epoch`); and `progressStartedAt`, which stays on the device and is
never synced. When the game starts storing something new, update both texts and
[review-notes.txt](review-notes.txt) in the same change.

| Localisation | Privacy policy URL |
|---|---|
| English (U.S.) and English (U.K.) | `https://roblib.dev/privacy-policy-jetshot.html` |
| Czech | `https://roblib.dev/privacy-policy-jetshot-cs.html` |

**Support URL:** a mandatory field, already set on the live listing.

**Marketing URL:** optional, feel free to leave it empty.

**Encryption:** the Info.plist sets `ITSAppUsesNonExemptEncryption = NO`, the way
the other two games do, so the export-compliance question no longer appears on
upload.

**Privacy manifest:** `jetshot/PrivacyInfo.xcprivacy` declares no tracking, no
collected data, and the one required-reason API the app uses: `UserDefaults`
(reason **CA92.1**, "access info from same app"). Progress synced to the player's
own iCloud is not collection, which matches the App Privacy answer above.

**App Review Information** → the note for the reviewer is in
[review-notes.txt](review-notes.txt). The game needs neither an account nor a demo
login — leave *Sign-in required* switched off. It does tell the reviewer that
ENDLESS only appears on the menu after level 1 is cleared, which is the one thing
about this build that looks like a missing feature if you do not know it.

## Release procedure

The same steps for every version. A new version in App Store Connect starts as a
copy of the live one — texts, screenshots and the App Preview — so most fields
only need comparing with this directory, not pasting.

1. In Xcode, `MARKETING_VERSION` is the new version and `CURRENT_PROJECT_VERSION`
   is higher than any build uploaded before, in both Debug and Release. Signing &
   Capabilities shows team `K6GM85X5D7` and bundle ID `cz.rob.jetshot`.
2. Each locale's `release_notes.txt` describes this version — only what changed
   since the previous one — and the check above prints `ALL CLEAN`.
3. If [privacy-policy/](privacy-policy/) has changed since the last release
   (`git log -- AppStore/privacy-policy`), copy both texts to the website and check
   that the two URLs above serve them. The policy has to describe the build under
   review.
4. App Store Connect → **+ Version or Platform** → *iOS*, numbered as
   `MARKETING_VERSION`. For each language, paste *What's New* from
   `release_notes.txt` and compare the other fields with this directory. Compare
   **App Review Information** with [review-notes.txt](review-notes.txt).
5. Screenshots and the App Preview carry over. Regenerate them only when the game
   looks noticeably different: run `Tools/appstore_media.sh` and
   `Tools/appstore_captions.sh`, then upload — see [screenshots.md](screenshots.md).
   The scripts produce English and Czech sets in one run; `en-GB` reuses the
   `en-US` media.
6. Xcode → Product → Archive → Distribute App → App Store Connect → Upload.
7. Once the build has processed, select it in the version's *Build* section.
8. **Add for Review** → *Submit*.
